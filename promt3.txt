Actúa como Arquitecto de Software y Desarrollador Full-Stack Android / Node.js. Tu objetivo es materializar las transacciones de negocio reales (cumpliendo con al menos el 50% del negocio planteado en base de datos local Room y en la Web API con Retrofit) y generar la documentación formal completa de requerimientos y arquitectura requerida para el Segundo Entregable:

1. Implementación de Transacciones CRUD en Base de Datos Local (SQLite-Room) y Web API (Retrofit):
   Garantiza que la aplicación ejecute transacciones activas de negocio cubriendo las operaciones de:
   - AGREGAR (Create):
     * Registrar nuevo aspirante: transacción que envía los datos a la API (POST /auth/register), recibe token y datos de aspirante, e inserta las entidades UsuarioEntity y AspiranteEntity en Room.
     * Cargar documento / multimedia: al seleccionar un archivo PDF o imagen, se genera la copia interna, se calcula el hash SHA-256, se inserta en DocumentoEntity (Room) con estado 'SUBIDO' / 'pendiente' y se envía vía Retrofit con @Multipart al endpoint POST /aspirantes/me/documentos.
     * Registrar comprobante de pago: formulario que guarda ComprobantePagoEntity en Room y lo sincroniza mediante POST /aspirantes/me/pago.
   - EDITAR (Update):
     * Actualizar datos personales: pantalla de perfil modifica nombre, teléfono o dirección; se envía PUT /aspirantes/me y actualiza AspiranteEntity en Room mediante Flow reactivo.
     * Marcar notificación como leída: evento en la lista de notificaciones que ejecuta PATCH /notificaciones/{id}/leida y actualiza NotificacionEntity.leida = true en Room, recalculando el badge del Home.
     * Revisión de Control Escolar: registrar dictamen (POST /admin/documentos/{id}/revision) que actualiza el estado del documento, recalcula el estatus del aspirante y genera una notificación.
   - VER / LISTAR (Read):
     * Listado reactivo de documentos vigentes mediante DocumentoDao.getDocumentosFlow() en DocumentsViewModel.
     * Listado de notificaciones y fechas importantes desde Room con sincronización de la API.
     * Dashboard del aspirante: consulta agregada de documentos aprobados, requeridos y notificaciones no leídas mostradas en HomeScreen.
   - ELIMINAR (Delete):
     * Eliminar documento: borrado de documentos no aprobados (DELETE /documentos/{id}) tanto en el servidor como en Room mediante DocumentoDao.deleteById(id).
     * Eliminar notificación: swipe o botón de borrado que elimina la fila en NotificacionDao y notifica a DELETE /notificaciones/{id}.
   - RECUPERAR (Restore / Cache Sync):
     * Recuperación de sesión: al iniciar la app, validar token guardado en DataStore; si está expirado, refrescar automáticamente con POST /auth/refresh; si es válido, recuperar datos del aspirante desde Room sin requerir red.
     * Sincronización de catálogos: descarga y almacenamiento en Room de carreras, estados y municipios para funcionamiento offline.
